數位學習AI應用

臨床 AI 需要能「動手」的智慧體嗎？用任務與授權決定 Agent、MCP 及系統架構

蔡泓恩 職能治療師更新：2026-09-12約 4 分鐘閱讀
本篇要回答的決策

查詢資料與改寫紀錄的風險不同。智慧體與 MCP 增加的是可串接的行動能力，不是臨床資格，也不會自動建立安全權限。

一、臨床問題

是否增加行動能力，應從必要工作而不是流行架構決定。假設系統只需整理公開衛教資料，固定查詢與人工確認可能足夠；若允許它讀病歷、排程及寄送內容，錯誤便不再只是螢幕上一段話。臨床問題是：哪些步驟可以自動化，哪些必須保留明確授權？

軟體各部分的責任需要讓臨床端看得懂。前端是使用者操作的介面，後端處理受控邏輯與服務存取，資料庫保存紀錄，API 是系統間約定的操作介面。這些角色可在不同規模的架構中實作，不表示每個小工具都必須採微服務或雲端資料庫。

二、有無臨床指引？正式規範如何建議

本題沒有支持自主智慧體直接處理臨床高風險決策的通用指引。MCP 官方安全文件處理的是系統串接的技術風險，包括授權與權杖使用；使用共同協定不代表每個工具可信，也不代表已取得讀取或改寫病歷的權限。[1]

Agent 是能依任務選擇工具並根據結果繼續行動的系統。MCP 則提供模型應用與工具／資料來源的共同溝通方式；它不是多智慧體的同義詞，也不是一定要使用 AI 才能完成的工作流程。固定規則足夠時，未必需要由模型反覆決定下一步。[1，技術概念與作者整理]

授權應由系統執行，而不是只寫在提示詞。只讀查詢、產生待審草稿與正式寫入應分成不同權限；私密服務金鑰不能放在人人可讀的網頁程式中，後端也需要身分與權限檢查。以下分層是安全開發原則的應用，不是 MCP 自動提供的完整保護。[2]

三、研究如何支持或限制這項建議

ReAct 研究說明交替推理與工具行動在特定任務有用。Yao 等人以問答、事實查核及互動環境比較不同方法，部分基準中 ReAct 的成功率較高。這些研究沒有測試病歷寫入、臨床責任或治療安全，不能把模擬任務的改善換算成醫療自主性。[3]

工具能力同時擴大未信任內容的影響範圍。間接提示詞注入研究展示被檢索內容可干擾應用及工具呼叫；因此單純多放一個「審查 Agent」，並沒有自動形成獨立、可靠的安全審查。兩個模型可能看到相同錯誤資料，或使用同樣不足的判準。[4；多智慧體限制為風險推論]

架構較複雜不代表比較安全。以上研究支持針對具體任務測試工具使用與攻擊情境，沒有證明多智慧體普遍優於固定流程。臨床單位應比較實際完成率、錯誤行動與人工審查負擔，而不是只比較系統有幾個角色。

如何應用與追蹤

臨床團隊可以要求一張可核對的操作清單。每項工具都列出讀什麼、能改什麼、用誰的權限，以及失敗後是否重試；對外發送應顯示實際收件人與內容，不能用「已確認」的模糊按鈕讓使用者承擔看不到的動作。

重試與停止條件需在正式使用前定義。排程或寫入逾時可能代表執行成功但回覆未到，盲目再送會造成重複紀錄；應由工程端設計可辨識重複的操作與狀態查詢。模型無法完成、來源衝突或權限不符時，應停止並交還人員，而不是增加更多 Agent 繼續嘗試。

四、結語：4 個重點

  • 先問任務是否真的需要自主選工具，固定流程可能已足夠。
  • MCP 是串接協定，不是安全或臨床能力認證。
  • 讀取、草稿與正式寫入要分權，敏感動作需可見且明確的授權。
  • 多智慧體與重試都需驗證，不能靠角色數量推定可靠。
